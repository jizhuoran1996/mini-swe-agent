# 轨迹采集、回放和状态

## 先采集真实 agent 解决过程

Builder 先构建任务环境与独立验证器，再让 agent 在该环境中完成源码构建、测试及产物交付。轨迹记录模型输入、输出和响应延迟，以及工具命令、依赖、实际结果、环境引用和后台工作。任务提示规定目标和验收，不规定人为的调用次数。

任务卡给出的官方命令是实现依据和可用工具路径，不要求 agent 必须逐条照抄。能够正确完成同一冻结交付目标的命令序列均可收集，并保存其真实资源画像。

## 回放真实构建

回放 driver 重用记录的模型输出，并在对应前置工具实际完成后模拟该次模型等待；随后真实执行下一条命令。不能用已记录的编译日志或构建产物替代本次编译，也不能在旧的预计完成时间到达时假定构建成功。

session 在默认生命周期下绑定同一逻辑 sandbox，跨调用保留源码、构建树、环境配置和声明的后台服务。重新使用 sandbox 执行另一条轨迹时恢复那条轨迹的初始状态。含增量场景的 trace 初始构建树必须有内容引用与生成条件；full build trace 初始树则不能含目标工程的编译结果。

## 动态结果

PID、后台 job handle、临时路径、动态端口和测试 worker ID 可能跨运行变化。采集时保留这些返回值的来源与后续使用关系；回放时通过变量绑定/句柄映射使用当前值。不要对 Bash 进行未受约束的字符串替换，也不要把动态资源名当成可复用的常量。

对无法可靠绑定的交互形式，先改造任务 wrapper 或使用稳定的任务范围路径与进程管理接口，再采集正式 trace。wrapper 只统一运行与证据接口，不替代实际构建工作。

## 可比较的输入

manifest 冻结任务/实例 ID、源码与依赖引用、artifact/cache 初始状态、工具链、构建目标、测试集合、并行配置、回放等待设置及计划到达时间。不同后端共享这些逻辑输入；实际 sandbox 创建、排队、调度、编译、测试和完成时间仍是测量结果。

编译的瞬时调度和内部线程交错不要求逐事件相同。测试的随机输入、生成文件和功能结果按任务规格固定或接受明确容差。不得按某次执行速度调整当次任务目标、跳过测试或提前终止尚未完成的进程来“匹配”旧轨迹。

`templates/replay_manifest.template.json` 给出冻结字段。回放成功的证据包括命令结果、目标产物和验证器结果，不等价于重现源任务的 agent 文字答案。
