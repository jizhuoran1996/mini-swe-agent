# BUILDv1-A01 (core profile) - zlib v1.3.1 source build and delivery

## What this delivers

A from-source build of zlib v1.3.1 (commit `51b7f2abdade71cd9bb0e7a373ef2610ec6f9daf`) into a private
prefix, the official `teststatic` self-test, and an independent C consumer compiled and run outside the
source tree, statically linked against the `libz.a` produced by this run.

The frozen **core** profile deliberately differs from the reference profile: it targets the complete
static library plus the official `teststatic` target. Shared-library variants (`testshared`, `test64`),
the dynamic consumer mapping check and the incremental patch variant are reference/extended scope and are
not claimed here even though the default `make` also links `libz.so`.

## Usage

```
python3 solution/main.py run    --input input --output output --jobs 4
python3 solution/main.py doctor --input input
python3 solution/main.py --help
```

* `--help` prints usage without touching the source or running any build.
* `doctor --input input` lists exact missing source/tool/dependency items, exits `78` if anything is
  missing and `0` when ready (source archive present and sha256-matching, C toolchain + make + POSIX
  shell + sed/awk/ar/ranlib/tar on `PATH`, bundled consumer source present).
* `run` refuses to start when `doctor` reports missing items, then performs, with preserved logs and exit
  codes for every command logged by the `buildkit` helper:
  1. `./configure --prefix=<output>/install`
  2. `make -j<jobs>` then `make -j<jobs> example minigzip`
  3. `make teststatic` (official upstream self-test, non-empty log required)
  4. `make install` (headers, `libz.a`, man page, `zlib.pc`)
  5. static consumer build outside the source tree: `gcc -O2 -Wall -I <prefix>/include consumer.c <prefix>/lib/libz.a`
  6. consumer execution against a deterministic 256 KiB binary fixture

## Consumer checks (all must pass)

* `zlibVersion() == "1.3.1"` (identity of the newly built library).
* `compress2`/`uncompress` one-shot round-trip over pseudo-random, structured and zero regions.
* Truncated compressed input is rejected (`uncompress != Z_OK`).
* Chunked streaming `deflate`/`inflate` round-trip ending in `Z_STREAM_END`.
* gzip file round-trip via `gzopen`/`gzwrite`/`gzread` with the `1f 8b` magic verified.
* `gzeof` is observed only after an explicit read-past-end probe, matching the documented zlib semantics
  (`gzeof` is set when a read returns zero bytes); the byte-count and content match are asserted first.

The consumer binary is built with the explicit path to this round's `libz.a`; no system `-lz` is used and
no artifact from a previous source tree is consulted.

## Outputs

* `output/logs/*.log` - one log per executed command (build, test, install, consumer).
* `output/commands.json`, `output/tests.json` - command and official-test evidence records.
* `output/install_manifest.json`, `output/install.tar.gz` - installed file hashes and the install archive.
* `output/install_identity.json` - header version, `libz.a` hash, pkg-config location, installed tree.
* `output/consumer_report.json` - consumer compile line, fixture size and per-check results.
* `output/run.json` - task id, source identity, profile, feature summary, official selectors.

## Limitations (honest)

* Only the core profile is claimed: static library + `teststatic`. `testshared` and `test64` are not run
  and no shared-linkage consumer is validated.
* `teststatic` is a single upstream shell target; the helper's generic parser may return no case count.
  In that case the raw log (`*** zlib test OK ***` plus `example`/`minigzip` output) is preserved as the
  evidence instead of a fabricated case count.
* No incremental patch, no cross-compilation, no installation outside the private prefix, and no network
  access are used.
* The delivered library is x86-64 Linux code generated by the container toolchain; no other platform is
  validated.
