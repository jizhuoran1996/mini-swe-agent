# BUILDv1-D07 · Agent 提示模板

Builder 在采集前补入冻结的 source/config/test manifest、可见输入路径、可用工具链和资源预算。初始请求与可选后续请求按真实依赖分阶段提供。

## 初始请求

从完整源代码编译 ClickHouse 单体工具包，交付可运行的 local/client/server 功能，并用官方 JSON 列测试和私有分析库检验产物。

### 提供的环境

- 固定版本的完整源代码、声明的子模块和测试数据已预置；目标项目的对象文件、已编译库、测试结果和安装目录为空。
- 编译器、引导工具及第三方依赖来源与版本写入输入清单；依赖缓存和本任务产物缓存分别管理。

### 工程范围

完整 clickhouse 单体可执行及本轮聚合 gtest；基线关闭 Rust 依赖分支，不构建外部集群或 Docker 集成环境。

### 工作要求

- 预置完整 contrib 子模块、声明的 Clang/lld 和构建工具，配置有界的 Linux CPU 目标。
- 编译 clickhouse 和真实 unit_tests_dbms，执行 ColumnObject.* 官方测试。
- 归档本轮二进制与配置，在私有目录验证 JSON/列式数据加载、查询及重新打开。

### 交付

- ClickHouse 私有工具归档、组件与依赖 manifest
- ColumnObject 测试枚举/结果及 unit_tests_dbms 来源
- local/server 消费者脚本、配置及重开数据验收

请使用提供的源码和依赖，在任务范围内真实构建并保存交付物。按照冻结的测试规格运行测试，保留实际结果、失败与日志。不得用预装同名软件、发布版二进制或空测试替代要求的构建和验证。允许使用官方构建工具与项目脚本，不限制解决过程的工具调用数量。

## 可选后续请求

对交付的临时数据库加入第二批数据并执行新的聚合查询，验证同一包能够继续使用此前状态。

如启用增量场景，builder 另外提供该任务卡指定并完成绑定的配置变化/补丁及验收要求；它仍属于同一个任务 ID。
