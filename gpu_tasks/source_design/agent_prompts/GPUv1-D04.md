# GPUv1-D04 · Agent任务提示模板

Builder在实例化时补充可见输入路径、冻结配置、允许的工具和设备预算。初始任务与后续请求分阶段交付；不把本文件中未来请求提前用于模拟再次访问。验证器的隐藏数据不出现在任务环境。

## 初始任务

根据问题和数据库模式，用本地 GPU 模型生成查询，实际执行只读 SQL，交付每个问题的 SQL、查询结果和错误记录，形成可以继续提交问题的数据查询工具。

### 来源和工作范围

birdsql/bird_sql_dev_20251106 的 dev_20251106 全 1,534 条，11 个对应 SQLite 数据库，Qwen2.5-Coder-32B-Instruct

### 交付要求

- queries.jsonl
- query_results/
- execution_status.jsonl
- database_hashes.json
- question_outcomes.jsonl（覆盖状态、SQL/答案语义状态、基础设施错误及 replay divergence 分列）

### 必须完成的工作

- 提取数据库模式并按 db_id 绑定问题
- 在 GPU 上逐题生成 SQL，校验只读查询并在本轮数据库执行
- 保存 SQL、规范化结果表和每题执行状态，保持数据库未修改

请在分配的环境中真实完成计算并保存可重载的产物。使用实例清单规定的输入ID、模型和工作量；若出现错误，保留失败项与实际状态。不要用外部模型API、预先生成的答案或重复数据替代规定的GPU工作。允许使用官方CLI和现有工具，无需刻意拆成多次调用。

## 后续请求（依实际依赖单独发出）

对同一数据库上的后续问题继续生成和执行查询，复用已加载模型与模式缓存，同时保留已有结果版本。

如果后续请求包含新输入，builder在采集前将完整输入集合分为互斥的initial和continuation子集；重复访问另行标记。
